Опис проекту
Flutter-застосунок імітує панель моніторингу розумної теплиці.

У застосунку реалізовано:
- паралельне початкове завантаження даних;
- FutureBuilder для початкового завантаження;
- StreamBuilder для оновлення показань датчиків;
- власні StreamController ;
- оновлення температури, вологості та освітленості приблизно кожні 1,5 секунд;
- окремі стани завантаження, помилки, порожніх даних та успішних даних;
- кнопку "Повторити";
- тайм-аут начального завантаження;
- кнопку «Пауза/Продовжити»;
- підсвічування картки при перевищенні порога;
- SnackBar при перевищенні граничного значення;
- помилку окремого датчика без остановки інших датчиків;
- коректне закриття таймера та потоків у dispose() .

Початкове асинхронне завантаження
Під час відкриття екрану паралельно завантажуються:
1. список датчиків;
2. порогові значення;
3. підсумок за день.
У файлі lib/services/fake_greenhouse_api.dart використано Future.wait :
final results = await Future.wait<Object>([
  loadSensors(),
  loadThresholds(),
  loadDailySummary(),
]).timeout(
  const Duration(seconds: 3),
);
FutureBuilder
Для початкового завантаження використано FutureBuilder<GreenhouseInitialData> у файлі lib/screens/greenhouse_screen.dart .

Future створюється в initState() , а не в build() :
_initialFuture = _api.loadInitialData();
FutureBuilder обробляє такі стани:
- завантаження;
- помилка;
- порожні дані;
- успішно отримані дані.
StreamBuilder
Для кожного датчика використано StreamBuilder<SensorReading> у файлі lib/widgets/sensor_card.dart .

Температура, вологість та освітленість надходять окремими потоками.
StreamController
У FakeGreenhouseApi створено власні StreamController<SensorReading>.broadcast() для температури, вологості та освітленості.

Ошибка окремого датчика передається через addError() і не закриває потік, тому інші датчики продовжують працювати.
Оновлення в реальному часі
Показання генеруються приблизно кожні 1,5 секунд через:
Timer.periodic(
  const Duration(milliseconds: 1500),
  ...
);
Порогові значення
Використані пороги:
- температура - 30 ° C;
- вологість – 80 %;
- освітленість - 850 лк.
При перевищенні порога:
- картка датчика підсвічується;
- відображається попереджувальний значок;
- показується SnackBar .
Для одного датчика SnackBar не показується частіше за один раз на 10 секунд.
Пауза та продовження
Кнопка "Пауза" зупиняє джерело подій - Timer.periodic .

Кнопка "Продовжити" запускає оновлення знову.
Тайм-аут
Початкове завантаження має тайм-аут 3 секунди:
.timeout(
  const Duration(seconds: 3),
)
При помилці користувач бачить повідомлення та кнопку «Повторити».
Імітація мережі
Справжні HTTP-запити не використовуються. Затримка сервера імітується через Future.delayed(...) .

У звичайному режимі використовується:
failureRate: 0.15
Для демонстрації гарантованої помилки тимчасово використовувалось:
failureRate: 1.0
Для демонстрації порожнього стану тимчасово використовувалось:
emptySensors: true
Після створення скріншотів застосунок повернуто до звичайного режиму роботи.
Dispose
При закритті екрана викликається:
@override
void dispose() {
  _api.dispose();
  super.dispose();
}
У сервісі метод dispose() скасовує Timer і закриває все StreamController .
